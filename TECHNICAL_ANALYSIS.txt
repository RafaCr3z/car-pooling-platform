                    PROBLEMAS IDENTIFICADOS NO CÓDIGO
═════════════════════════════════════════════════════════════════════════════════

PROBLEMA #1: Falta de JWT Parsing
────────────────────────────────
Localização: auth-service/pom.xml
Descrição: JwtTokenProvider é mencionado mas JWT library não está nas dependências
Impacto: 🔴 CRÍTICO - Authentication fará erro se não tiver dependência JWT
Solução:
  Adicionar ao auth-service/pom.xml:
  <dependency>
      <groupId>io.jsonwebtoken</groupId>
      <artifactId>jjwt-api</artifactId>
      <version>0.12.3</version>
  </dependency>
  <dependency>
      <groupId>io.jsonwebtoken</groupId>
      <artifactId>jjwt-impl</artifactId>
      <version>0.12.3</version>
      <scope>runtime</scope>
  </dependency>
  <dependency>
      <groupId>io.jsonwebtoken</groupId>
      <artifactId>jjwt-jackson</artifactId>
      <version>0.12.3</version>
      <scope>runtime</scope>
  </dependency>

PROBLEMA #2: Falta de Spring Security em Trip Service
───────────────────────────────────────────────────────
Localização: trip-service/pom.xml
Descrição: Endpoints REST não estão protegidos com Spring Security
Impacto: 🟡 IMPORTANTE - Qualquer pessoa pode criar/deletar viagens
Solução:
  Adicionar ao trip-service/pom.xml:
  <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-security</artifactId>
  </dependency>

PROBLEMA #3: Falta de Swagger/OpenAPI
──────────────────────────────────────
Localização: Todos os serviços (springdoc.api-docs.path está configurado)
Descrição: Configuração exists mas dependency não está no pom.xml
Impacto: 🟡 IMPORTANTE - Swagger UI não funciona
Solução:
  Adicionar a todos os serviços com REST APIs:
  <dependency>
      <groupId>org.springdoc</groupId>
      <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
      <version>2.0.2</version>
  </dependency>

PROBLEMA #4: Falta de OpenFeign no Frontend
────────────────────────────────────────────
Localização: frontend-service/pom.xml
Descrição: Usa WebClient em vez de OpenFeign
Impacto: 🟡 MÉDIO - Funcionará mas não é padrão para microserviços
Solução:
  Frontend uses WebClient (OK for UI layer)
  MAS backend services should use OpenFeign

PROBLEMA #5: Falta de Error Handling Global
─────────────────────────────────────────────
Localização: Todos os controllers
Descrição: Sem @ControllerAdvice ou @RestControllerAdvice
Impacto: 🟡 IMPORTANTE - Erros não tratados adequadamente
Impacto na API: Respostas inconsistentes (alguns 500, alguns 400)
Solução:
  Criar GlobalExceptionHandler.java em cada serviço:
  @RestControllerAdvice
  public class GlobalExceptionHandler {
      @ExceptionHandler(EntityNotFoundException.class)
      public ResponseEntity<ApiError> handleNotFound(EntityNotFoundException e) {
          return ResponseEntity.status(404).body(new ApiError(...));
      }
  }

PROBLEMA #6: Falta de Logging Estruturado
───────────────────────────────────────────
Localização: Services e Controllers
Descrição: Sem @Slf4j ou logging explícito
Impacto: 🟡 IMPORTANTE - Difícil debugar em produção
Solução:
  Adicionar @Slf4j do Lombok a todos os Services
  Adicionar log.info(), log.debug(), log.error() nos pontos críticos

PROBLEMA #7: Falta de Validação em DTOs
────────────────────────────────────────
Localização: LoginRequest, RegisterRequest, CreateTripRequest
Descrição: Sem @NotNull, @NotBlank, @Email etc.
Impacto: 🟡 IMPORTANTE - Validação inadequada
Solução:
  Adicionar Bean Validation annotations:
  @Data
  public class LoginRequest {
      @NotBlank(message = "Email is required")
      @Email(message = "Email must be valid")
      private String email;
      
      @NotBlank(message = "Password is required")
      @Size(min = 6, message = "Password must be at least 6 characters")
      private String password;
  }

PROBLEMA #8: Falta de Transações
────────────────────────────────
Localização: Services críticos
Descrição: Sem @Transactional em métodos que modificam dados
Impacto: 🟡 IMPORTANTE - Risco de inconsistência de dados
Solução:
  Adicionar @Transactional a métodos que fazem CRUD:
  @Service
  @Transactional
  public class TripService {
      public TripDTO createTrip(CreateTripRequest request) {
          ...
      }
  }

FLUXO 1: Registo e Login
────────────────────────
1. Utilizador acessa http://localhost:3000
2. Frontend exibe home page (público)
3. Utilizador clica "Registar"
4. Frontend exibe formulário (auth/register.html)
5. Utilizador preenche dados e submete
6. Frontend POST para http://localhost:3000/register
7. AuthController recebe dados
8. AuthService chama POST http://localhost:8080/api/auth/register
9. API Gateway roteia para auth-service
10. AuthService salva User no PostgreSQL
11. Frontend redireciona para /dashboard
12. Frontend exibe dashboard protegido (requer login)

Status: ✅ Implementado (MAS sem segurança CORS)

FLUXO 2: Pesquisa e Reserva de Viagem
──────────────────────────────────────
1. Utilizador autenticado acessa /trips/search
2. Frontend exibe formulário com filtros
3. Utilizador insere origem, destino, data
4. Frontend POST para http://localhost:3000/trips/search
5. TripController recebe filtros
6. TripService chama GET http://localhost:8080/api/trips/search?...
7. API Gateway roteia para trip-service
8. TripService retorna lista de viagens compatíveis
9. Frontend renderiza trips/search-trips.html com resultados
10. Utilizador clica "Reservar" numa viagem
11. Frontend POST para http://localhost:3000/trips/reserve
12. TripController recebe CreateReservationRequest
13. TripService chama POST http://localhost:8080/api/trips/reservations
14. Trip Service salva Reservation no PostgreSQL
15. Frontend redireciona para /trips/my-reservations

Status: ✅ Implementado (MAS sem integração payment-service)

FLUXO 3: Criar Viagem
─────────────────────
1. Utilizador autenticado (DRIVER) acessa /trips/create
2. Frontend exibe formulário (trips/create-trip.html)
3. Utilizador preenche: origem, destino, data, lugares, preço
4. Frontend POST para http://localhost:3000/trips/create
5. TripController recebe CreateTripRequest
6. TripService chama POST http://localhost:8080/api/trips
7. Trip Service salva Trip no PostgreSQL
8. Trip Service pode chamar Vehicle Service para validar veículo (NÃO IMPLEMENTADO)
9. Frontend redireciona para /trips/my-trips
10. Frontend lista viagens criadas pelo utilizador

Status: ✅ Implementado (MAS sem validação de veículos)
