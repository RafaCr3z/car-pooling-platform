║                        COMUNICAÇÃO ENTRE SERVIÇOS                             ║
╚═══════════════════════════════════════════════════════════════════════════════╝

Trip Service precisa de dados do Auth Service:
  Trip Service --[OpenFeign]--> Auth Service (8081)
  @FeignClient(name = "auth-service")
  public interface AuthServiceClient { ... }

Payment Service precisa de dados do Trip Service:
  Payment Service --[OpenFeign]--> Trip Service (8082)
  @FeignClient(name = "trip-service")
  public interface TripServiceClient { ... }

Todos usam Circuit Breaker:
  @CircuitBreaker(name = "serviceName", fallbackMethod = "fallback")
  Retorna dados em cache se serviço falhar

╔═══════════════════════════════════════════════════════════════════════════════╗
║                         FLUXO DE UMA RESERVA                                  ║
╚═══════════════════════════════════════════════════════════════════════════════╝

1. Utilizador acede Frontend (Port 3000)
   │
2. Faz login em /api/auth/login (via API Gateway)
   │
   ├─> Auth Service (8081) valida credenciais
   │   └─> Retorna JWT token
   │
3. Pesquisa viagens em /api/trips/search (via API Gateway)
   │
   ├─> Trip Service (8082) retorna viagens disponíveis
   │   └─> Pode chamar Location Service (8086) para filtrar por proximidade
   │
4. Seleciona viagem e faz reserva em /api/trips/reservations (via API Gateway)
   │
   ├─> Trip Service (8082) cria reserva
   │   ├─> Valida lugares disponíveis
   │   ├─> Calcula custo automático
   │   └─> Atualiza estado da viagem
   │
5. Sistema processa pagamento via Payment Service (8084)
   │
   ├─> Payment Service processa pagamento
   │   ├─> Divide custo entre passageiros
   │   ├─> Gera recibo
   │   └─> Registra no histórico
   │
6. Admin visualiza em /api/admin/statistics (via API Gateway)
   │
   ├─> Admin Service (8085) retorna estatísticas
   │   ├─> Número total de viagens
   │   ├─> Receita total
   │   ├─> CO₂ poupado
   │   └─> Utilizadores ativos

╔═══════════════════════════════════════════════════════════════════════════════╗
║                      ESCALABILIDADE - MÚLTIPLAS INSTÂNCIAS                     ║
╚═══════════════════════════════════════════════════════════════════════════════╝

Com Docker Compose, podemos escalar:

  docker-compose up -d --scale trip-service=3

Isto cria 3 instâncias de Trip Service:
  • trip-service_1 (porta 8082)
  • trip-service_2 (porta 8083)
  • trip-service_3 (porta 8084)

Eureka automaticamente descobre as 3 instâncias
API Gateway faz load balancing entre as 3
